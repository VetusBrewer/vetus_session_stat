Вот что должен делать скрипт. Копировать папку с файлами *.py в другую папку, там запускать компилятор питона 2.7.16, *.py удалять, папку запаковывать в архив с нужным названием, копировать этот архив в другое место на компьютере с перезаписью старого файла, папку удалять.









Для этой задачи идеально подходит **PowerShell**. Он встроен в Windows, отлично работает с файловой системой и умеет управлять внешними программами.

Ниже приведен готовый скрипт. Вам нужно будет только изменить пути в блоке «НАСТРОЙКИ».

### Скрипт (файл `build-package.ps1`)

powershellКопировать

```python
# --- НАСТРОЙКИ (ИЗМЕНИТЕ ЭТИ ПУТИ) ---
# 1. Откуда брать исходники
$SourceDir = "C:\Path\To\Source\PythonFiles"

# 2. Куда копировать для сборки (рабочая папка)
$BuildDir = "C:\Path\To\Build\Temp"

# 3. Путь к интерпретатору Python 2.7.16
$PythonExe = "C:\Python27\python.exe"

# 4. Куда положить готовый архив
$DestinationDir = "C:\Path\To\Final\Archives"

# 5. Имя архива (можно добавить дату)
$ArchiveName = "MyPythonApp_v1.0.zip"
# -------------------------------------

# --- БЛОК ВЫПОЛНЕНИЯ ---

# Формируем полные пути
$TargetWorkDir = Join-Path $BuildDir "package_content"
$ArchivePath = Join-Path $DestinationDir $ArchiveName

Write-Host "=== Сборка пакета начата ==="

try {
    # 1. Очищаем старую рабочую папку, если она есть
    if (Test-Path $TargetWorkDir) {
        Remove-Item -Recurse -Force $TargetWorkDir
    }

    # 2. Создаем чистую рабочую папку
    New-Item -ItemType Directory -Path $TargetWorkDir | Out-Null

    # 3. Копируем только .py файлы из источника
    Write-Host "Копирование исходных файлов..."
    Get-ChildItem -Path $SourceDir -Filter "*.py" -Recurse | Copy-Item -Destination $TargetWorkDir

    # 4. Запускаем компилятор Python 2.7 (py_compile)
    Write-Host "Компиляция файлов..."
    # Формируем команду для питона: -m py_compile .
    $compileArgs = @("-m", "py_compile", ".")
    $process = Start-Process -FilePath $PythonExe -ArgumentList $compileArgs -WorkingDirectory $TargetWorkDir -NoNewWindow -Wait -PassThru

    if ($process.ExitCode -ne 0) {
        throw "Ошибка компиляции Python. Код выхода: $($process.ExitCode)"
    }

    # 5. Удаляем исходные .py файлы
    Write-Host "Удаление исходных .py файлов..."
    Get-ChildItem -Path $TargetWorkDir -Filter "*.py" -Recurse | Remove-Item -Force

    # 6. Проверяем, есть ли что архивировать (на случай, если компиляция не создала .pyc)
    $filesToArchive = Get-ChildItem -Path $TargetWorkDir -File
    if ($filesToArchive.Count -eq 0) {
        throw "Папка для сборки пуста. Архивировать нечего."
    }

    # 7. Создаем архив (встроенными средствами Windows)
    Write-Host "Создание архива..."
    # Убедимся, что папка назначения существует
    if (-not (Test-Path $DestinationDir)) {
        New-Item -ItemType Directory -Path $DestinationDir | Out-Null
    }

    Compress-Archive -Path (Join-Path $TargetWorkDir "*") -DestinationPath $ArchivePath -Force

    Write-Host "=== Сборка успешно завершена ==="
    Write-Host "Готовый файл: $ArchivePath"

} catch {
    Write-Host "!!! ПРОИЗОШЛА ОШИБКА !!!"
    Write-Host $_.Exception.Message
} finally {
    # 8. Гарантированная очистка рабочей папки
    if (Test-Path $TargetWorkDir) {
        Remove-Item -Recurse -Force $TargetWorkDir
    }
}
```

### Как это запустить

1. Скопируйте код в текстовый редактор (например, *VS Code* или *Блокнот*).

2. Измените пути в блоке **«НАСТРОЙКИ»**:
   
   - `$SourceDir`: папка, где лежат ваши исходные `.py` файлы.
   - `$BuildDir`: любая пустая папка для временных файлов (скрипт сам создаст внутри неё подпапку).
   - `$PythonExe`: **самое важное**. Укажите точный путь к файлу `python.exe` версии 2.7.16. Обычно это `C:\Python27\python.exe`.
   - `$DestinationDir`: папка, где должен лежать финальный `.zip` файл.
   - `$ArchiveName`: как будет называться ваш архив.

3. Сохраните файл с расширением `.ps1` (например, `build-job.ps1`).

4. Нажмите правой кнопкой мыши по кнопке «Пуск» → **Windows PowerShell (Администратор)**.

5. Разрешите выполнение скриптов для этого сеанса (введите команду и нажмите Enter):
   
   powershellКопировать
   
   ```python
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   ```

6. Перейдите в папку со скриптом (команда `cd`) и запустите его:
   
   powershellКопировать
   
   ```python
   .\build-job.ps1
   ```

### Как это работает (пошагово)

1. **Очистка:** Скрипт удаляет следы прошлых сборок, чтобы не было мусора.
2. **Копирование:** Забирает только файлы `.py`. Флаг `-Recurse` внутри `Get-ChildItem` позволит забрать их и из подпапок, если они есть.
3. **Компиляция:** Команда `python.exe -m py_compile .` заставляет встроенный модуль Python пройтись по текущей папке и создать рядом с каждым `script.py` файл `__pycache__\script.cpython-27.pyc`.
4. **Удаление:** Исходники удаляются, остаются только байт-коды (`.pyc`).
5. **Архивация:** `Compress-Archive` создает `.zip`. Ключ `-Force` перезапишет файл, если он уже существует в папке назначения.
6. **Finally:** Блок `finally` сработает всегда (даже если произошла ошибка), чтобы временная папка не осталась висеть на диске.

### Вопрос

а вот это вот что?

### Ответ

Это **скомпилированный байт-код Python**.

Когда вы запускаете обычный текстовый файл `script.py`, программа `python.exe` делает следующее:

1. Читает ваш текст.
2. **Компилирует** его во внутреннее представление — байт-код. Это не машинный код (как в C++), а инструкции для «виртуальной машины» Python.
3. **Сохраняет** этот байт-код в специальную папку `__pycache__` с расширением `.pyc`, чтобы в следующий раз не тратить время на компиляцию текста, если файл не менялся.
4. **Выполняет** этот байт-код.

### Что внутри `.pyc` файла

- Это бинарный (нечитаемый человеком) файл.
- В нём хранятся инструкции (`opcodes`), которые понимает интерпретатор Python 2.7.
- Имя файла `script.cpython-27.pyc` означает: «скомпилировано версией CPython 2.7».

### Зачем мы это делаем в скрипте

Ваша задача — скрыть исходный код `.py` от глаз пользователя, но оставить программу рабочей.

- Если мы просто удалим `.py` и оставим пустую папку, программа не запустится.
- Если мы оставим `.py`, пользователь сможет прочитать ваш алгоритм.
- **Решение:** Мы компилируем `.py` в `.pyc`, а затем удаляем исходный `.py`.

Интерпретатор Python (и версия 2.7, и 3.x) прекрасно умеет работать с `.pyc` файлами. Если он видит рядом с собой папку `__pycache__` или файл с именем модуля, он подхватит байт-код и выполнит его, даже если исходного текста `.py` нет.

**Важный нюанс:** такой способ «защиты» кода — слабый. Байт-код `.pyc` легко декомпилируется обратно в читаемый Python-код с помощью специальных утилит (например, `uncompyle6`). Это скорее защита от случайного просмотра, чем от профессионального реверс-инжиниринга.

### Вопрос

Блин. случайно энтер раньше времени нажал... Вот это вот что в скрипте:
Compress-Archive

### Ответ

Это встроенная команда (*летлет*, *cmdlet*) **PowerShell**, которая создаёт архивный файл (обычно формата `.zip`).

По сути, это стандартная команда Windows для сжатия данных, доступная прямо из терминала без установки сторонних программ вроде *WinRAR* или *7-Zip*.

### Как она работает в вашем скрипте

Строка выглядела так: `Compress-Archive -Path (Join-Path $TargetWorkDir "*") -DestinationPath $ArchivePath -Force`

Разберём её по частям:

- **`Compress-Archive`**: имя самой команды (создать архив).
- **`-Path (Join-Path $TargetWorkDir "*")`**: что именно мы кладём в архив.
  - `Join-Path` — это безопасный способ склеить путь к папке (`$TargetWorkDir`) и маску файла (`"*"` — то есть «всё содержимое папки»).
  - Это гарантирует, что в архиве окажутся сами файлы, а не папка, внутри которой лежат файлы.
- **`-DestinationPath $ArchivePath`**: куда сохранить готовый архив. Здесь мы указываем полный путь, включая имя файла (например, `C:\Итог\мой_проект.zip`).
- **`-Force`**: ключ, который говорит: «Если файл с таким именем уже существует — **перезапиши его** без лишних вопросов». Это критически важно для автоматизации, иначе скрипт бы падал с ошибкой при повторном запуске.

### Важные особенности

1. **Формат:** команда создаёт архивы формата **ZIP**. Она не умеет делать `.rar` или `.7z`.
2. **Версия Windows:** эта команда появилась в Windows 10 и Windows Server 2016. Если вы запустите этот скрипт на Windows 7, он выдаст ошибку, так как этой команды в той версии *PowerShell* ещё не было. Для старых систем пришлось бы вызывать внешний архиватор (например, `7z.exe`) через `Start-Process`.

### Вопрос

у меня инструкция по этому поводу "запакуйте с помощью 7-zip в зип формат без сжатия". Оно может без сжатия? я так понимаю чем паковать без разницы - важно зип формат и отсутствие сжатия...

### Ответ

Да, вы абсолютно правы. Для автоматизации не важно, какая именно программа создаёт архив, если она соблюдает два условия: формат **ZIP** и уровень сжатия **«Без сжатия»** (Store).

Команда `Compress-Archive` в PowerShell **не умеет** создавать ZIP-архив без сжатия. У неё нет параметра для выбора уровня компрессии. Она всегда пытается сжать файлы (алгоритм Deflate).

Поэтому, раз в инструкции строго указан **7-Zip**, нужно использовать его. Это правильный подход, так как 7-Zip даёт полный контроль над процессом.

### Как изменить скрипт под 7-Zip

Вам нужно будет заменить блок создания архива на вызов внешней программы `7z.exe`.

1. **Добавьте путь к 7-Zip в настройки.** Укажите, где лежит файл `7z.exe`.
   
   powershellКопировать
   
   ```python
   # --- НАСТРОЙКИ ---
   $SevenZipExe = "C:\Program Files\7-Zip\7z.exe" # Стандартный путь установки
   # ------------------
   ```

2. **Замените команду `Compress-Archive`.** Вместо:
   
   powershellКопировать
   
   ```python
   Compress-Archive -Path (Join-Path $TargetWorkDir "*") -DestinationPath $ArchivePath -Force
   ```
   
   Напишите вызов через `Start-Process`:
   
   powershellКопировать
   
   ```python
   Write-Host "Создание архива (7-Zip, без сжатия)..."
   
   # Проверяем, существует ли 7z.exe
   if (-not (Test-Path $SevenZipExe)) {
      throw "Ошибка: не найден 7z.exe по пути $SevenZipExe"
   }
   
   # Формируем аргументы для 7-Zip:
   # a       - команда "добавить в архив"
   # -tzip   - тип архива zip
   # -mx0    - уровень сжатия 0 (без сжатия / Store)
   $arguments = @("a", "-tzip", "-mx0", "`"$ArchivePath`"", "`"$TargetWorkDir\*`"")
   
   # Запускаем процесс
   $process = Start-Process -FilePath $SevenZipExe -ArgumentList $arguments -Wait -NoNewWindow -PassThru
   
   if ($process.ExitCode -ne 0) {
      throw "7-Zip вернул ошибку. Код выхода: $($process.ExitCode)"
   }
   ```

### Разбор аргументов 7-Zip

- `a` (Add): команда добавления файлов в архив.
- `-tzip`: принудительно задаёт формат ZIP (хотя по умолчанию он и так ZIP, инструкция требует точности).
- `-mx0`: самый важный ключ. `mx` — это уровень сжатия, а `0` означает «No compression» (скопировать файлы как есть, просто обернув в ZIP-контейнер).
- ``"`"$ArchivePath`"``: кавычки нужны на случай, если в пути есть пробелы. Символ ``` ` `` в PowerShell экранирует кавычку.

Этот вариант будет на 100% соответствовать вашей инструкции.
