Да, это классическая задача автоматизации, и настроить её можно. Однако делать это «в лоб» (автоматический коммит и пуш при каждом сохранении файла) — **плохая практика**. Это создаст тысячи коммитов, захламит историю репозитория и может привести к потере данных, если файл запишется наполовину.

Правильный подход — использовать **Git-хуки (Git Hooks)**. Это скрипты, которые *Git* запускает сам при определенных событиях.

### Рекомендуемый сценарий: «Умный» авто-пуш

Вместо того чтобы пушить при каждом изменении, мы настроим систему так:

1. Файл в папке `rawlog` меняется.
2. Скрипт ждет 1–2 секунды (чтобы запись файла точно завершилась).
3. Скрипт проверяет, изменился ли файл на самом деле.
4. Если да — добавляет его в *Git*, делает **один** коммит с понятным сообщением (например, с текущей датой) и пушит.

### Как это реализовать (Windows + PowerShell)

Внутри вашей папки с проектом есть скрытая папка `.git`. Внутри неё есть папка `hooks`.

1. Перейдите в папку `.git\hooks\`.
2. Найдите там файл `post-commit.sample` или создайте новый файл с именем **`post-save.ps1`** (или любое другое имя).
3. Нам понадобится «наблюдатель» за файлами. Самый простой способ — использовать *Task Scheduler* (Планировщик задач Windows) или бесконечный цикл в *PowerShell*.

#### Вариант 1: Скрипт на PowerShell (самый простой для запуска вручную)

Создайте файл `auto-git.ps1` в корне вашего проекта (рядом с папкой `.git`):

powershellКопировать

```python
# Путь к папке, за которой следим
$WatchFolder = "rawlog"
# Имя файла, который меняем
$FileName = "log.txt" 
$RepoPath = (Get-Location).Path

Write-Host "Запущен авто-пуш. Нажмите Ctrl+C для остановки."

# Запускаем вечный цикл
while ($true) {
    $FilePath = Join-Path $WatchFolder $FileName

    # Проверяем, существует ли файл и менялся ли он за последние 2 секунды
    if (Test-Path $FilePath) {
        $LastWriteTime = (Get-Item $FilePath).LastWriteTime
        $TimeSpan = New-TimeSpan -Start $LastWriteTime -End (Get-Date)

        if ($TimeSpan.TotalSeconds -lt 2) {
            # Файл изменился недавно. Ждем секунду, чтобы запись завершилась.
            Start-Sleep -Seconds 1

            # Выполняем команды Git
            Set-Location $RepoPath
            git add $FilePath
            $timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
            git commit -m "Auto-update log: $timestamp"
            git push

            Write-Host "Файл '$FilePath' обновлен и запушен в $timestamp"

            # Ждем 5 секунд, чтобы не спамить коммитами, если файл меняется часто
            Start-Sleep -Seconds 5
        }
    }
    # Проверяем каждые 0.5 секунды
    Start-Sleep -Milliseconds 500
}
```

**Как использовать:**

1. Откройте *PowerShell* в корне проекта.
2. Разрешите выполнение скриптов (если не делали этого раньше): `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`
3. Запустите скрипт: `.\auto-git.ps1`

Оставьте это окно открытым. Теперь при любом изменении `rawlog\log.txt` скрипт сам сделает коммит и пуш.

#### Вариант 2: Планировщик задач Windows (Task Scheduler) — более «чистый» способ

1. Создайте скрипт `update-log.ps1` (упрощенная версия без цикла):
   
   powershellКопировать
   
   ```python
   $RepoPath = "C:\путь\к\вашему\проекту"
   $FilePath = "rawlog\log.txt"
   
   Set-Location $RepoPath
   git add $FilePath
   
   # Проверяем, есть ли изменения для коммита
   $Status = git status --porcelain
   if ($Status) {
      $timestamp = Get-Date -Format "Auto-update: yyyy-MM-dd HH:mm"
      git commit -m $timestamp
      git push
   }
   ```

2. Откройте **Планировщик задач Windows**.

3. Создайте «Базовую задачу» (Basic Task).

4. Триггер: **«При входе в систему»** (или «При запуске компьютера»).

5. Действие: **«Запустить программу»**.
   
   - Программа: `powershell.exe`
   - Аргументы: `-File "C:\путь\к\вашему\проекту\update-log.ps1"`

6. В свойствах задачи (галочка «Выполнить с наивысшими правами») и во вкладке «Параметры» поставьте **«Выполнять задачу по мере её готовности. Если пропуск запуска — выполнить немедленно»**.

Этот способ запустит скрипт один раз, он сделает коммит, если нужно, и завершится.

**Важное предупреждение:** автоматический коммит — это удобно, но вы теряете контроль над историей. Если файл `log.txt` запишет «мусор», он улетит в репозиторий. Для логов обычно используют другие инструменты, но если задача именно такая — хуки или *PowerShell*-наблюдатель справятся.



### Оптимальный сценарий: Планировщик задач Windows (Task Scheduler)

Поскольку файл меняется не от ваших рук, а от внешней программы, бесконечный цикл на PowerShell (`while ($true)`) — это лишняя нагрузка на процессор. Лучше всего использовать Планировщик задач.

#### Пошаговая настройка

1. **Создайте скрипт.** Создайте в корне вашего проекта файл `update-log.ps1` со следующим содержимым:

powershellКопировать

```python
# --- НАСТРОЙКИ ---
# Вставьте сюда полный путь к папке вашего проекта
$RepoPath = "C:\Absolute\Path\To\Your\Project" 
$RelativeFilePath = "rawlog\log.txt"
# ------------------

# Переходим в папку репозитория
Set-Location -Path $RepoPath

# Полный путь к файлу для Git
$FullFilePath = Join-Path $RepoPath $RelativeFilePath

# Проверяем, существует ли файл (вдруг внешняя программа еще не создала его)
if (Test-Path $FullFilePath) {

    # Добавляем файл в индекс
    git add $RelativeFilePath

    # Проверяем, есть ли что коммитить (git add не выдает ошибку, если файл не изменился, 
    # но git status покажет, что изменений нет)
    $Status = git status --porcelain $RelativeFilePath

    if ($Status) {
        # Если изменения есть - делаем коммит
        $timestamp = Get-Date -Format "auto: yyyy-MM-dd HH:mm:ss"
        git commit -m "Log update: $timestamp"

        # И сразу пушим
        git push

        Write-Host "[$timestamp] Файл обновлен и отправлен в репозиторий."
    } else {
        # Файл существует, но идентичен тому, что в Git. Ничего не делаем.
        # Это экономит ресурсы и не создает пустых коммитов.
    }
}
```

2. **Настройте Планировщик задач (Task Scheduler).**
- Откройте «Планировщик заданий» в Windows.
- **Действие → Создать задачу...** (не «простую задачу», а именно «Задачу» для гибкости).
- **Вкладка «Общие»**:
  - Имя: `Auto Git Push Log`.
  - Выберите «Выполнять вне зависимости от регистрации пользователя» (Run whether user is logged on or not).
  - Поставьте галочку «Выполнять с наивысшими правами» (Run with highest privileges) — это важно, чтобы Git имел доступ к файлам.
- **Вкладка «Триггеры»**:
  - Нажмите «Создать...».
  - Выберите «По событию» (On an event). Это самый эффективный способ.
  - **Журнал (Log):** `Microsoft-Windows-Shell-Core/Operational` (или `System`).
  - **Источник (Source):** `Shell-Core` (или `Winlogon`).
  - **Код события (Event ID):** **4624** (это событие входа в систему/создания нового сеанса) — *или, что лучше для файлов, см. примечание ниже*.
  - *Примечание:* События по изменению файла отслеживать сложно. Самый надежный «железный» триггер — **по времени**. Например, «При запуске системы» + «Повторять каждые 5 минут бесконечно». Для логов, которые прилетают раз в час, этого более чем достаточно.
- **Вкладка «Действия»**:
  - Действие: «Запуск программы».
  - Программа: `powershell.exe`.
  - Аргументы: `-ExecutionPolicy Bypass -File "C:\Absolute\Path\To\Your\Project\update-log.ps1"`.
  - «Рабочая папка» (Start in): `C:\Absolute\Path\To\Your\Project`.

### Почему этот метод лучше

1. **Нет холостого хода:** Скрипт не висит в памяти постоянно. Он просыпается раз в 5 минут, делает свою работу за полсекунды и засыпает.
2. **Нет конфликтов:** Он не зависит от того, открыт ли у вас VS Code, сохраняете ли вы файлы вручную или запущен ли другой скрипт.
3. **Чистая история:** Скрипт проверяет `git status`. Если внешняя программа перезаписала файл тем же самым содержимым, коммита не будет. История не засорится.
